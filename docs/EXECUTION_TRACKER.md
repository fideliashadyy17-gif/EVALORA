## Increment: student imports and spreadsheet-safe reporting

- Replaced the unmaintained npm `xlsx@0.18.5` package with the pinned third-party `@e965/xlsx@0.20.3` SheetJS repackaging, including both server import and browser template generation. This version is above the affected ranges for the reported prototype-pollution and ReDoS advisories. It is third-party packaging, not an official SheetJS registry distribution; dependency provenance and future security advisories still require monitoring. This does not guarantee safe processing of malicious files or address compressed-file expansion/resource exhaustion. Existing XLS/XLSX/CSV workflows remain supported.
- Shared CSV report/export encoding prefixes spreadsheet-formula-like *text* with an apostrophe, quotes carriage returns, and retains numeric cells. Applied to the student template and import report as well as shared admin/customer `toCsv` exports. The apostrophe is intentionally present in raw CSV, including phone-like text beginning with `+`; users importing raw CSV should account for that. Spreadsheet-specific interpretation can vary; this is risk reduction, not a proof against every spreadsheet implementation.
- No migration: changes only affect file parsing and generated CSV, not persisted schema or records. Reviewed production schema and migration history above.
- Real parser tests generate/read XLS and XLSX, check multiple sheets, leading-zero text, output bounds and CSV escaping; extraction authorization tests use mocked session/parser boundaries. See command results and release entry below.

## Increment: option-ID stability and fail-closed grading (Phases 1–2, partial)

- **Implemented on the branch, not deployed.** Workspace and Super Admin question saves compare persisted options with the submitted options before changing question details. When labels, correctness, order and rich content are unchanged, the action no longer deletes and recreates option IDs. Equivalent legacy plain-text-to-rich-document conversions are also recognized. A failed options read stops before the question write; a changed option still uses the existing non-atomic delete/reinsert flow. This is a best-effort reduction in accidental ID churn, not a database-enforced lock, immutable versioning or a concurrency guarantee. Changing the prompt, correct key, points, type, configuration, or options can still alter historical and active papers, and direct writes can bypass these application checks. The Super Admin editor now explicitly warns to duplicate rather than modify historical questions. Its existing duplication action now preserves class/subject/curriculum/source metadata and reports a failed option copy as an incomplete draft instead of success. Duplicate creation remains non-atomic, and the incomplete draft is retained for review. Workspace duplication remains unavailable.
- Objective scoring validates missing/malformed keys, stale or unknown selected option IDs, answer shape, finite numeric values, tolerance and matching keys. A stale option no longer silently receives an incorrect zero. Legitimate zero, negative numeric answers and numeric strings remain supported; invalid/unverifiable answers fail grading for human investigation. Unscored open-ended, poll and slide answers remain manual/not scorable. Live answer submissions with unverifiable marking return an error without inserting an answer or updating participant score.
- Examination grading calculates all results before writing any marks. If a later answer or key cannot be verified, no grade writes are issued for that batch. Writes remain separate and may still partially succeed on a database/concurrency error; exam submission, marking and grade totals are not atomic. In particular this change **does not recover original option text or marking keys after edits**, detect edits where IDs remain unchanged, guarantee paper consistency, or correct scores already written. It may prevent final submission of a stale or malformed saved response; staff must investigate and correct it, not force a zero.
- Publication validation rejects missing/null/blank numeric keys, invalid tolerance, missing accepted short-answer keys, and invalid/duplicate matching prompts. It applies on subsequent saves/publication, not retroactively to stored assessments. Production aggregate checks found 1,076 single-choice/true-false questions, all with exactly one correct option; all eight existing single-choice exam answers with a stored option ID currently refer to an option on their question. These aggregates are not comprehensive integrity or privacy tests. No migration or production data change in this increment.
