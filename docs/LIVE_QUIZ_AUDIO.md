# EVALORA Live Quiz audio

## Original library

The files in `public/audio/live/` are original EVALORA compositions generated by `scripts/audio/generate_live_audio.py`. They contain no third-party recordings, samples, or melodies and are not copies of Kahoot audio. The synthesis uses layered, smooth pitched voices and melodic arpeggios; there are no drum or percussion tracks. The generator is retained in the repository for reproducibility.

| Asset | Use |
| --- | --- |
| `lobby-loop.wav` | Waiting room and pre-question countdown loop |
| `game-start.wav` | Organizer start / initial countdown cue |
| `question-transition.wav` | New question cue |
| `question-loop.wav` | Under-question focus bed |
| `countdown-suspense.wav` | Original rising musical phrase, aligned to the last ten seconds |
| `time-up.wav` | Rounded descending time-up cadence |
| `answer-submitted.wav` | Private participant answer-recorded acknowledgement |

| `leaderboard.wav` | Ranking reveal cue |

| `podium-victory.wav` | Podium / winner celebration |
| `game-complete.wav` | Closing cadence |

## Playback design

- Only the Public Live Screen plays shared music and event cues. The organizer monitor remains silent, preventing doubled room audio when it and a projector are open together. Participant devices receive only optional personal answer-submission and answer-reveal feedback, never shared background music.
- The screen and students must explicitly enable audio with a user gesture. Screen audio uses Web Audio decoded buffers, preloads core files following the gesture, caches fetches, loops the two music beds, and cleans up its context on exit. If playback is blocked, visual game functionality is unaffected.
- Cues are keyed by session/question/phase to suppress duplicate playback after polling or reconnects. The last-ten-second phrase is launched from the server-provided question deadline using the screen's server-clock offset; time-up uses that same authoritative deadline rather than an independent countdown timer.
- Organizer settings are saved in the live session: music/effects toggles, mute-all, master gain, separate music/effects gains, and restore defaults. Participant sound preference is local to that browser and join code.

## Audio checks and limitations

Assets are 22.05 kHz, 16-bit stereo PCM WAV. The generator's post-render sample peak target is approximately -1.3 dBFS (the ten-second suspense phrase is approximately -1.7 dBFS), with no clipped samples. `scripts/test-live-audio-assets.mjs` validates asset presence, headers, format, sample peaks, clipping and RMS program level. These are digital peak/RMS checks, not LUFS or true-peak mastering measurements; no claim of measured LUFS is made. The current workbench does not provide an audio audition/listening tool, so subjective listening on phone speakers/headphones and device-specific browser QA must still be completed by a human before production approval.
